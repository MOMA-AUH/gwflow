# Domain docs

This repository uses a single domain context.

Before exploring, read root `CONTEXT.md` and any relevant decisions under `docs/adr/`. If a root `CONTEXT-MAP.md` is introduced, follow it to the relevant contexts and their ADRs instead. Missing domain documents do not block work or require upfront scaffolding.

Use the glossary's terms in specs, tickets, implementation discussions, and tests. If a needed concept is absent, determine whether it is unnecessary scope or a gap to resolve through domain modeling.

Surface conflicts with an existing ADR explicitly rather than silently overriding it.
