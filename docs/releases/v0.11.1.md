# gwflow v0.11.1

gwflow v0.11.1 fixes Task recovery, source loading, and ownership checks for retained outputs. It also reduces filesystem metadata and repeated work when reading local termination history.

### Highlights

- Interrupted creation of a Task attempt no longer exposes incomplete initial records. A later invocation can create an attempt without adopting unfinished private records.
- Commands load current workflow and imported Task source after rapid edits, including edits with unchanged file size and modification timestamp.
- Recorded Tasks keep ownership of their results directories when omitted from a workflow, including after cleanup. Other Tasks cannot claim the same directory or its ancestors or descendants. Conflicts stop preview and execution before retained results change.
- Local termination history uses one workflow ledger and a writer lock instead of one file per Submission. The ledger preserves exact Submission identities. History increases stored bytes rather than the number of files.
- Ownership checks scale through sorted paths. Repeated termination lookups share validation of an unchanged ledger within one observation, reducing repeated copying and validation of the full history.

### Compatibility and deployment

This remains a pre-1.0 release. The [compatibility guidance](https://github.com/MOMA-AUH/gwflow/blob/v0.11.1/docs/reference.md#compatibility) applies. Before upgrading, finish or cancel affected jobs and establish that all computation jobs, lifecycle jobs, and their descendants are inactive. A cancellation request alone does not establish inactivity.

The new termination ledger does not migrate earlier loose receipts. Stop the earlier local scheduler and establish inactivity independently. Use the existing `gwflow recover` operation before reusing earlier work, as described in the [operating guide](https://github.com/MOMA-AUH/gwflow/blob/v0.11.1/docs/operating.md).

The deployment profile remains Linux and Bash with Python 3.12, exactly gwf 3.0.0, and deployment-provided Apptainer 1.5.4 for containers. Local schedulers remain specific to each resolved workflow directory. The default local walltime remains one hour, including preparation and completion jobs.

Compatibility comparisons use the native gwf 3 bootstrap. They do not establish compatibility with earlier gwf 2 workflow state or the future stable compatibility baseline. This pre-1.0 release does not establish a stable baseline.

```sh
conda activate gwflow-0111
gwf --version
gwflow --version
```
