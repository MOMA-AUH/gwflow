gwflow v0.4.1 removes the ignored Task working-directory option and requires current storage identity records before they can authorize managed operations.

### Highlights

- Reject `Task(working_dir=...)`, including `working_dir=None`, instead of silently ignoring it. Remove the argument from Task factories; host and container computation run in private managed work. `Workflow(working_dir=...)` remains available for workflow-relative path resolution, and managed temporary directories and the `managed_tmpdir` opt-out are unchanged.
- Require the current inode-only directory identity format for managed storage ownership. Older device-plus-inode records, missing identities, and malformed identities cannot establish ownership for Reuse, submission, mutation, or cleanup. Validate ready workspace evidence before selecting unfinished attempts so retired records cannot authorize resubmission.
- Document the pre-1.0 policy: each release supports its documented authoring interface and durable record format, without a cross-version Reuse, retry, or repair guarantee. Keep historical validation records clearly scoped to the release they describe.

This patch removes acceptance of the older device-plus-inode record representation, superseding that compatibility guarantee in v0.4.0. Finish or deliberately stop existing jobs before upgrading, and use the matching old release for inspection or cleanup of old runs. Incompatible runs need separate workflow and storage locations; unsupported factories and records have no automatic conversion, migration, or adoption path. Keep bookkeeping with its work and retained results. Initialized storage cannot be relocated.

BeeGFS workers and frontends may still use different local device numbers; current durable identities use inode numbers, while same-host placement and rename/removal checks retain their device checks. Storage roots remain trusted deployment-provided locations, and replacement of an entire root is not detected. Container execution continues to require deployment-provided Apptainer and prepared images.

The verified setup is Python 3.12 and gwf 2.1.1. Release preparation CI passed the installed-package and Conda test suites, real Apptainer 1.5.4 execution, and local container acceptance checks. The release workflow built and tested the Conda artifact, published it to the [MOMA-AUH channel](https://anaconda.org/MOMA-AUH/gwflow), then installed the published package and passed the cleanup and Reuse check. The [v0.4.0 validation record](https://github.com/MOMA-AUH/gwflow/blob/v0.4.1/docs/validation-v0.4.0.md) preserves prior Linux, Slurm, and BeeGFS observations and their limits; those Slurm checks were not rerun for this patch. See the [README](https://github.com/MOMA-AUH/gwflow/blob/v0.4.1/README.md) for setup, examples, and upgrade guidance.
