# gwflow v0.8.0

v0.8.0 adds interactive workflow inspection, mandatory command tracking, and explicit operator recovery for unresolved submissions.

## Highlights

- `gwflow status` opens a cached interactive browser on capable terminals. Browse groups, Tasks, jobs, history, and bounded logs; search and filter locally, refresh manually, and opt into live following for one selected log. Use `--static` for a single formatted report or `--plain` for undecorated output. Redirected status remains plain and static.
- Run, cancellation, cleanup, and recovery reports lead with outcomes. Details retain exact receipts, and failures preserve actionable diagnostics and any confirmed partial results. Unexpected errors retain their traceback.
- Managed computation commands are always tracked. Command edits require a new Task attempt under the usual safeguards. Remove `use_spec_hashes=false`; managed workflows reject this opt-out. Use explicit `--force` for untracked package or environment changes.
- `gwflow recover TASK` records an operator assertion that the whole Task is inactive, resolving uncertainty in its current attempt. It refuses observed queued or running jobs, submits and cancels nothing, and does not certify successful computation. Investigate first, then preview and run normally; valid successful work remains eligible for preservation.

## Compatibility and deployment

This remains a pre-1.0 release. The installed compatibility regression journeys cover the recorded bootstrap/candidate pair, including completed work after cleanup, partial computation, interrupted installation, and Repair. They do not promise compatibility with all earlier releases or establish the future v1.0.0 stable baseline. Before changing environments, finish or cancel affected jobs and confirm that every computation and lifecycle job is inactive. A cancellation request alone does not establish inactivity. Live upgrades, mixed-version workers, and storage relocation remain unsupported.

The deployment profile remains Linux, Python 3.12, gwf 2.1.1, local workers and Slurm, with deployment-provided Apptainer 1.5.4 for containers. Current automated checks use local workers, real containers, and controlled Slurm commands without production-cluster access. Historical live-cluster observations are identified separately. Representative production-pipeline validation on the actual cluster is follow-up work, not a completed check or a release gate. Captured 100-Task/1,000-job browser measurements are not full-workflow or cluster benchmarks.

## Setup and verification

Install the published release:

```sh
conda create -n gwflow-080 --override-channels -c MOMA-AUH -c gwforg -c conda-forge 'gwflow=0.8.0'
conda activate gwflow-080
gwflow --version
```
