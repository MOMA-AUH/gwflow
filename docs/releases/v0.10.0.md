# gwflow v0.10.0

gwflow v0.10.0 adds JSON status reports and a command for waiting on existing Task attempts. It also improves terminal output and release validation.

### Highlights

- `gwflow status --json` provides Task states, progress, attempt identifiers, notices, and structured errors for scripts and monitoring. Add `--details` to include jobs, recorded submission names, backend IDs, and observed states. Removed jobs remain visible while they are active or their outcomes are unknown.
- `gwflow wait` observes selected Tasks and their required upstream Tasks without submitting, retrying, or canceling work. It reports completion, failures, and conditions that require another command. Messages use stderr; stdout stays empty.
- `gwflow wait --timeout SECONDS` limits the whole command, including loading, inspection, scheduler queries, and polling pauses. Timeout returns exit code `124`; Ctrl+C returns `130`. Submitted jobs can continue after waiting stops.
- Waiting uses a compact live table with Task states and job progress in terminals. Redirected output reports concise changes and retains failure explanations. Interactive status also gives lifecycle job names clearer styling.
- Release validation captures exact Conda dependencies, restores the tested runtime, and compares independent environments. CI selects compatibility baselines from the checked-out descriptor.

### Compatibility and deployment

This remains a pre-1.0 release. The [compatibility guidance](https://github.com/MOMA-AUH/gwflow/blob/v0.10.0/docs/reference.md#compatibility) continues to apply. Before an upgrade, finish or cancel affected jobs and confirm that every computation and lifecycle job is inactive. A cancellation request alone does not establish inactivity.

The deployment profile remains Linux and Bash with Python 3.12, gwf 2.1.1, and deployment-provided Apptainer 1.5.4 for containers. Automated checks use local workers, real containers, and controlled Slurm commands. Live production-cluster checks are not part of this release validation.

The new runtime checks prepare for preserved stable-release baselines from v1.0.0 onward. This release continues to use the provisional source baseline; it does not establish the future stable compatibility baseline.

The packaged example Tasks now require gwflow `>=0.10.0,<0.11`. Their package versions advance to `0.5.0` to distinguish the updated dependency metadata. Reinstall both example packages when upgrading an existing example environment.

### Setup and verification

```sh
conda create -n gwflow-0100 --override-channels -c MOMA-AUH -c gwforg -c conda-forge 'gwflow=0.10.0'
conda activate gwflow-0100
gwflow --version
```
