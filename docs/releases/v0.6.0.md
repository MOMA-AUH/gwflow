gwflow v0.6.0 introduces a dedicated `gwflow` command line with consistent Task selection, scoped execution, and a shorter getting-started guide built around installation from the MOMA-AUH conda channel.

### Highlights

- Use `gwflow` for managed workflows, with `run`, `status`, `logs`, `clean`, `config`, and `workers`. Ordinary `gwf.Workflow` workflows continue to use `gwf`; each executable reports when a workflow belongs to the other. Workflow discovery still defaults to `workflow.py:gwf`, with `--file PATH[:OBJECT]` for alternatives. Help and version information work without a workflow file.
- Select whole Tasks consistently with positional exact names and quoted globs in `run`, `status`, and `clean`. Every supplied selector must match; unmatched selectors fail the invocation before submission, Task-state changes, or cleanup deletion. With no selectors, commands consider the whole workflow.
- Run selected Tasks with their required upstream dependencies. `gwflow run C --force` starts a fresh attempt for C while checking upstream Tasks normally and reusing valid results. Runtime blockers and image acquisition are limited to the execution scope, so an unrelated unavailable image does not prevent selected work. Whole-workflow declaration validation, storage ownership, and protection of active or uncertain consumers still apply.
- Preview execution with `gwflow run --dry-run`, using the same selectors, upstream dependencies, and force semantics as an actual run. Add `--details` for deeper diagnostics. Status focuses on selected Tasks and relevant upstream blockers: no selectors gives the grouped overview, exact names or globs give Task rows, and `--details` adds computation and lifecycle jobs. Run and status preserve complete names and diagnostics by wrapping long terminal text; plain and redirected reports remain complete.
- Preview disposable-work cleanup with `gwflow clean`, then add `--delete` to remove eligible work while preserving retained results, logs, and Reuse records. Task selectors also find recorded attempts after a declaration is removed. Previews list each recorded attempt and its eligibility; repeatable `--attempt UUID` still supports deliberate cleanup of eligible inactive attempts that ordinary cleanup keeps.
- Follow a concise README quickstart covering local workers, selection, status, logs, force, cleanup, and Reuse. Conda version and download badges are restored, and installation uses the MOMA-AUH channel. Detailed authoring, container, lifecycle, and storage guidance now lives in the linked reference; packaged examples and the validation guide use the current CLI.

This changes the managed command interface. Replace managed `gwf` invocations with `gwflow`, `clean-work` with `clean`, `explain` with `run --dry-run`, `--force-task NAME` with positional selection plus `--force`, and cleanup `--task NAME` with positional Task selectors. Group and public-job selection and the `task:`/`job:` namespaces are removed from Task commands; logs still select individual jobs. Use `status '*'` instead of `status --instances`; `--no-truncate` is unnecessary because reports retain complete text. The lean CLI also omits `info`, `touch`, `cancel`, `--no-deps`, `--group`, and status `--endpoints`/`--format`; cancellation remains a backend operation. Workflow discovery, backend configuration, and storage locations retain their existing conventions.

The pre-1.0 compatibility and transition guidance continues to apply: finish or deliberately stop existing jobs before switching versions, use the matching old release for inspection or cleanup of old runs, and use separate workflow and storage locations for incompatible records. There is no automatic conversion, migration, or adoption of unsupported factories or records, and initialized storage cannot be relocated. Container execution requires deployment-provided Apptainer; registry images require a shared cache visible at the same path on frontend and compute nodes with matching CPU architectures. Python and conda packages require Rich `>=15.0.0,<16`. Packaged summary and report examples remain version `0.4.0` and accept gwflow `>=0.5.3,<0.7`.

The verified setup is Python 3.12, gwf 2.1.1, and Apptainer 1.5.4. Release preparation [CI](https://github.com/MOMA-AUH/gwflow/actions/runs/38295353935) passed 420 installed-package tests, 14 real Apptainer local acceptance tests, and the conda package suite (376 passed, 44 container-dependent skips) and packaged-example smoke test. The [release workflow](https://github.com/MOMA-AUH/gwflow/actions/runs/38297501147) built and tested the tagged conda artifact, published it to the [MOMA-AUH channel](https://anaconda.org/MOMA-AUH/gwflow), then installed the published package and passed the cleanup and Reuse check.

See the [README](https://github.com/MOMA-AUH/gwflow/blob/v0.6.0/README.md) for installation and the runnable quickstart, and the [reference](https://github.com/MOMA-AUH/gwflow/blob/v0.6.0/docs/reference.md) for detailed usage and compatibility guidance. The [validation guide](https://github.com/MOMA-AUH/gwflow/blob/v0.6.0/docs/validation/README.md), [registry acceptance record](https://github.com/MOMA-AUH/gwflow/blob/v0.6.0/docs/validation/registry-images/acceptance.md), and [container validation record](https://github.com/MOMA-AUH/gwflow/blob/v0.6.0/docs/validation/containers/acceptance.md) preserve earlier local, Slurm, and BeeGFS observations; those Slurm checks were not rerun for this release.
