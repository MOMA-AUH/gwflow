# gwflow v0.10.1

gwflow v0.10.1 fixes local cancellation, cancellation of earlier submissions, and status reporting for new Tasks with unavailable inputs. It also adds a synthetic bioinformatics example and improves release publication.

### Highlights

- Local cancellation stops and reaps computation descendants before reporting inactivity. Retry and cleanup remain blocked when termination cannot be established.
- Cancellation includes earlier submissions in a selected Task's current attempt, including recovered submissions that reappear as active. Completed work remains available.
- Status reports new Tasks with unavailable inputs as blocked instead of aborting inspection of the workflow.
- Task declarations reject invalid local target names, including names with a trailing newline, before creating work or submitting jobs.
- The new [synthetic read-alignment example](https://github.com/MOMA-AUH/gwflow/tree/v0.10.1/example) uses Minimap2, Samtools, and MultiQC. It demonstrates retained outputs, cleanup, and reuse with bundled input data and public container images.
- CI runs the full Conda suite in four parallel groups, including real-container tests. Publication reuses the exact tested package and can resume after a partial upload.

### Compatibility and deployment

This remains a pre-1.0 release. The [compatibility guidance](https://github.com/MOMA-AUH/gwflow/blob/v0.10.1/docs/reference.md#compatibility) continues to apply. Before an upgrade, finish or cancel affected jobs and confirm that every computation and lifecycle job is inactive. A cancellation request alone does not establish inactivity.

Stop old local jobs and restart workers with the upgraded `gwflow workers` before submitting new work. Older workers remain available for observation, but new managed submissions and verified cancellation require updated workers. Slurm retains its existing cancellation behavior.

The deployment profile remains Linux and Bash with Python 3.12, gwf 2.1.1, and deployment-provided Apptainer 1.5.4 for containers. Automated checks use local workers, real containers, and controlled Slurm commands. Live production-cluster checks are not part of this release validation.

This release uses the provisional source baseline. It does not establish the future stable compatibility baseline. The former packaged examples now live under `tests/fixtures/packaged_tasks/` as test fixtures.

### Setup and verification

```sh
conda create -n gwflow-0101 --override-channels -c MOMA-AUH -c gwforg -c conda-forge 'gwflow=0.10.1'
conda activate gwflow-0101
gwflow --version
```

Runtime qualification and all four 15-case independent runtime comparisons also passed.

All three smoke journeys passed in a fresh installation from the MOMA-AUH channel. The final check matched the installed filename, version, channel, and SHA256 to the tested artifact.
