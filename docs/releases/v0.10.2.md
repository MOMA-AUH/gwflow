# gwflow v0.10.2

gwflow v0.10.2 improves local-worker recovery, connection failures, dependency validation, and log viewing. It also strengthens release publication checks and updates the operating examples.

### Highlights

- Local workers preserve termination evidence across restarts and backend configuration changes. Retry and cleanup remain blocked when job inactivity cannot be established.
- Connections to local workers stop after three attempts, with a one-second timeout per connection. Errors identify the configured host and port and point to `gwflow workers`.
- `gwflow wait` reports worker outages and continues polling. Its overall `--timeout` includes connection attempts and inspections.
- Dependency validation avoids repeated traversal of shared upstream Tasks and checks for evidence changes before accepting their results.
- Individual log streams remain tied to the selected submission while they are read and displayed. Log viewing releases the frontend lock so other commands can proceed.
- Release publication distinguishes local verification from GitHub Actions and checks the source CI run before upload. Conda builds now require setuptools 84.2.1 or newer.

### Compatibility and deployment

This remains a pre-1.0 release. The [compatibility guidance](https://github.com/MOMA-AUH/gwflow/blob/v0.10.2/docs/reference.md#compatibility) continues to apply. Before an upgrade, finish or cancel affected jobs and confirm that every computation and lifecycle job is inactive. A cancellation request alone does not establish inactivity.

Stop old local jobs and restart workers with the upgraded `gwflow workers` before submitting new work. Older workers remain available for observation, but new managed submissions and verified cancellation require updated workers. Slurm retains its existing cancellation behavior.

Earlier local workers did not retain durable termination evidence. After an upgrade, their Tasks can remain blocked even when outputs exist. Once every job and descendant in an affected Task is confirmed inactive, use `gwflow recover TASK` to record that operator assertion. Recovery preserves valid completed work and submits no jobs.

The deployment profile remains Linux and Bash with Python 3.12, gwf 2.1.1, and deployment-provided Apptainer 1.5.4 for containers. Automated checks use local workers, real containers, and controlled Slurm commands. Live production-cluster checks are not part of this release validation.

This release uses the provisional source baseline. It does not establish the future stable compatibility baseline.

### Setup and verification

```sh
conda create -n gwflow-0102 --override-channels -c MOMA-AUH -c gwforg -c conda-forge 'gwflow=0.10.2'
conda activate gwflow-0102
gwflow --version
```
