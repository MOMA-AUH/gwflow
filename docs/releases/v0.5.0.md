gwflow v0.5.0 gives managed workflows a consistent Task overview, shared execution plans, and explicit submission outcomes across status, explain, dry-run, and run.

### Highlights

- See one status row per Task in dependency order, with a primary state, Jobs completed, and concise aggregate details. Progress includes preparation, computation, and completion: fresh attempts start at zero, retries retain valid steps, Repair reopens completion, and cleaned-work Reuse stays fully complete. Unknown progress is explicit. Blockage, failure, and cancellation take precedence while ongoing jobs remain visible in the details.
- Use a static Rich terminal presentation with a summary frame, state symbols, and slim snapshot progress bars. `--plain` removes decoration, `--no-truncate` preserves full text in terminals, and redirected output is automatically plain and untruncated. Narrow terminals retain states and numeric counts; required notices always wrap in full. Presentation adds no scheduler polling or live refresh.
- Expand the complete Task lifecycle with `--details` on all four command routes. Selecting a Task, an individual job, or a matching computation-target group reveals the whole owning Task, with preparation first and completion last. Detailed views include reasons, attempts, paths, public job names, available backend IDs, and logs. Inspection filters retain whole-workflow validation.
- Compare the same **Task / Next action / Why** plan in explain, dry-run, and run, using Run, Continue, Retry, Finish, Repair, Reuse, Wait, Defer, and Blocked. Notices disclose retained-result replacement, workflow-wide submission blockage, and when another invocation is required after upstream recovery. Current Task state remains distinct from its planned treatment.
- See what an actual run submitted: totals count only confirmed new backend acceptances, including lifecycle jobs, and Tasks receiving those jobs. Interrupted submissions distinguish confirmed jobs, uncertain acceptance, and planned jobs not attempted. Accepted jobs may continue; submission is not rolled back. Reports and required notices use stdout, with operational diagnostics and command errors on stderr.

Managed status now filters by the primary Task state and selects complete Tasks. Legacy managed `--format` modes are replaced by the Task presentation; those modes and their original selection rules remain available for ordinary gwf workflows. Rich `>=14.1,<15` is now a direct dependency. The packaged summary and report examples are version `0.4.0` and require gwflow `0.5.x`. Progress counts steps, not time, effort, output correctness, or eligibility for Reuse. Execution and recovery semantics remain unchanged, and managed run remains a whole-workflow operation.

The pre-1.0 compatibility and transition guidance continues to apply: finish or deliberately stop existing jobs before switching versions, use the matching old release for inspection or cleanup of old runs, and use separate workflow and storage locations for incompatible records. There is no automatic conversion, migration, or adoption of unsupported factories or records, and initialized storage cannot be relocated. Container execution still requires deployment-provided Apptainer; registry images require a shared cache visible at the same path on frontend and compute nodes with matching CPU architectures.

The verified setup is Python 3.12, gwf 2.1.1, and Apptainer 1.5.4. Release preparation CI passed the installed-package and Conda test suites, real Apptainer execution, and local container acceptance checks. The [release workflow](https://github.com/MOMA-AUH/gwflow/actions/runs/37363427977) built and tested the Conda artifact, published it to the [MOMA-AUH channel](https://anaconda.org/MOMA-AUH/gwflow), then installed the published package and passed the cleanup and Reuse check. The [registry acceptance record](https://github.com/MOMA-AUH/gwflow/blob/v0.5.0/docs/validation-registry.md) and [container validation record](https://github.com/MOMA-AUH/gwflow/blob/v0.5.0/docs/validation-v0.4.0.md) preserve prior local, Slurm, and BeeGFS observations and their limits; those Slurm checks were not rerun for this release. See the [README](https://github.com/MOMA-AUH/gwflow/blob/v0.5.0/README.md) for command examples, setup, and upgrade guidance.
