# gwflow v0.12.0

gwflow v0.12.0 adds logical inputs: named datasets with an author-declared identity and a selected set of physical files. Completed Tasks can reuse their results across equivalent file formats, including when the source files are offline.

### Highlights

- `Task.logical_input()` declares a dataset's identity, named files, and decoding metadata. Consuming targets receive a JSON descriptor with usable file paths.
- Each attempt freezes its selected files and metadata. Workers check their paths, sizes, and modification times before computation, output acceptance, and initial result installation.
- Completed Tasks can reuse results after their logical source files disappear or change representation, provided the declared identity and other tracked computation remain valid.
- Repair can restore retained outputs from checked work while logical sources are offline. Interrupted Completion and Repair can resume when their recorded evidence proves the installed results or checked work remain valid.
- Container targets receive descriptors with staged member paths. Custom descriptor paths use `stage_as`, with collisions rejected before submission.
- The alignment example demonstrates switching paired FASTQs to a SPRING archive, reusing completed Tasks, and forcing fresh computation from the archive.
- Documentation CI accepts Markdown files directly inside `docs/releases/`, so release-note archive PRs use the lightweight checks.

### Compatibility and deployment

gwflow trusts the author's claim that equal logical identities represent equivalent decoded data. Values that change computation must remain in the logical identity or another tracked declaration. Keep target declarations and command templates stable across representations.

Fresh computation, explicit force, and representation changes before initial Completion require available physical inputs. Ordinary inputs and container images retain their availability requirements.

This remains a pre-1.0 release. Before upgrading, establish that all affected computation jobs, lifecycle jobs, and descendants are inactive. A cancellation request alone does not establish inactivity. See the [operating guide](https://github.com/MOMA-AUH/gwflow/blob/v0.12.0/docs/operating.md) and [logical input reference](https://github.com/MOMA-AUH/gwflow/blob/v0.12.0/docs/reference.md#logical-inputs).

The deployment profile remains Linux and Bash with Python 3.12, exactly gwf 3.0.0, and deployment-provided Apptainer 1.5.4 for containers. Local schedulers remain specific to each resolved workflow directory. The default local walltime remains one hour, including preparation and completion jobs.

Compatibility comparisons use the native gwf 3 bootstrap. They do not establish compatibility with earlier gwf 2 state or the future stable compatibility baseline. This release does not establish a stable baseline.

### Setup and verification

```sh
conda create -n gwflow-0120 --override-channels -c MOMA-AUH -c gwforg -c conda-forge 'gwflow=0.12.0'
conda activate gwflow-0120
gwf --version
gwflow --version
```
