# gwflow v0.12.1

gwflow v0.12.1 makes Task registration faster for large workflows, fixes two local backend failure paths, and adds installed-upgrade checks for logical inputs.

### Highlights

- Task registration uses indexes to check job names and result directories. In a controlled Linux container benchmark, median registration time for 800 independent Tasks fell from 10.71 seconds to 0.062 seconds. [Benchmark record](https://github.com/MOMA-AUH/gwflow/blob/v0.12.1/docs/validation/task-registration/measurements.json)
- Local recovery refuses to proceed when the scheduler still reports an active job for the affected Submission name. When a supervisor confirms that a launch was rejected, the scheduler releases its reserved capacity.
- Installed-upgrade tests cover reuse with logical source files offline, retry of an incomplete attempt with the same files, and creation of a fresh attempt when the selected files change before Completion. [Compatibility record](https://github.com/MOMA-AUH/gwflow/blob/v0.12.1/docs/validation/compatibility/logical-inputs.json)
- Release qualification requires the next patch, minor, or major version relative to GitHub's latest published non-prerelease.

### Compatibility and deployment

Before upgrading, confirm that all affected jobs and descendants are inactive, and keep workflow and storage paths unchanged. This is a pre-1.0 release. The supported profile uses Linux and Bash, Python 3.12, exactly gwf 3.0.0, and deployment-provided Apptainer 1.5.4 for container Tasks. [Operating guide](https://github.com/MOMA-AUH/gwflow/blob/v0.12.1/docs/operating.md)
