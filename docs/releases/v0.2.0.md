gwflow v0.2.0 adds `gwf explain` to preview what a whole-workflow run would do and why, before submitting jobs. It also adds configurable resources for generated Completion jobs.

### Highlights

- Preview ordinary and forced runs with `gwf explain` and `gwf explain --force`. Each Task shows its current condition, planned action, and a concise reason; inspection submits no jobs or changes Completion evidence.
- Use `--details` to inspect target states, planned treatment, and upstream cause chains. Filter the display to one exact Task name without changing whole-workflow planning.
- Set workflow-wide `completion_defaults` to override inherited resources for generated Completion jobs without changing ordinary target options or invalidating Reuse.
- Try the packaged three-Task workflow example, which composes independently installed Task implementations and reuses completed work after intermediate cleanup.

The verified setup is Python 3.12, gwf 2.1.1, and the local backend. Cluster backends, including Slurm, have not been verified for this release. Use whole-workflow `gwf run`; target selectors, `--group`, and `--no-deps` are unsupported. See the [README](https://github.com/MOMA-AUH/gwflow/blob/v0.2.0/README.md) for examples and setup instructions.
