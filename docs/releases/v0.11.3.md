# gwflow v0.11.3

gwflow v0.11.3 improves recovery and retry safety, downstream Task planning during Repair, log access, and JSON status output.

### Highlights

- Slurm recovery refuses a Task while any exact Submission name from its current attempt remains queued or running. This includes earlier submissions and jobs whose acknowledgement was lost.
- Offline recovery reads local termination receipts from the recorded scheduler directory when the workflow uses a custom working directory.
- Managed backends publish tracking files atomically, protecting existing job tracking when a frontend write is interrupted.
- Failures before backend submission record proven non-admission, allowing an ordinary retry after the underlying problem is resolved. Uncertain submissions still require recovery.
- Local workers release capacity after failures during setup before process launch, so independent queued jobs can proceed.
- Repair deferral reaches all downstream Tasks, including new Tasks and Tasks with changed commands. Independent Tasks can still proceed.
- Preview and run reject generated log filenames that exceed filesystem limits before submitting work. The error identifies names to shorten.
- Log commands and the status browser find managed job logs when `Workflow(working_dir=...)` differs from the workflow file directory.
- JSON status keeps plugin startup diagnostics on stderr, including buffered native output, so stdout remains valid JSON.
- CI reuses verified container fixtures and cached Conda downloads, selects lighter checks for prose-only changes, and runs the complete installed suite without sharding. Release qualification always runs the full pipeline for the exact tagged commit.

### Compatibility and deployment

This remains a pre-1.0 release. Before upgrading, finish or cancel affected jobs and establish that all computation jobs, lifecycle jobs, and their descendants are inactive. A cancellation request alone does not establish inactivity. See the [operating guide](https://github.com/MOMA-AUH/gwflow/blob/v0.11.3/docs/operating.md) and [compatibility guidance](https://github.com/MOMA-AUH/gwflow/blob/v0.11.3/docs/reference.md#compatibility).

The deployment profile remains Linux and Bash with Python 3.12, exactly gwf 3.0.0, and deployment-provided Apptainer 1.5.4 for containers. Local schedulers remain specific to each resolved workflow directory. The default local walltime remains one hour, including preparation and completion jobs.

Compatibility comparisons use the native gwf 3 bootstrap. They do not establish compatibility with earlier gwf 2 workflow state or the future stable compatibility baseline. This pre-1.0 release does not establish a stable baseline.
