gwflow v0.4.0 adds Apptainer execution to managed Tasks: select prepared images per target, stage declared inputs under predictable names, and keep checked Completion, Reuse, retry, repair, and work cleanup across host and container commands.

### Highlights

- Select a deployment-provided local SIF with `image=` and mix host targets and targets using different images in one Task. Only authored commands run inside the image; preparation, output checks, retained-result transfer, and Completion stay on the host.
- Stage declared container inputs as symlinks in private work. Use `stage_as=` for duplicate basenames, nested layouts, and explicitly declared reference/index companions. Request source directories read-only and private work and selected scratch read-write.
- Track image pathname, size, and modification time independently of command hashes. Image changes refresh the whole Task and its consumers; unrelated Tasks remain reusable. Unavailable images block decisions while preserving results, and status, explain, and dry-run report the reason.
- Run container commands with a clean environment and private managed `TMPDIR` by default. With `managed_tmpdir=False`, forward the job's selected scratch directory without adopting it for cleanup. Failed commands cannot establish Completion; eligible retries preserve successful siblings and get fresh work and scratch.
- Complete packaged container producers, clean their disposable work, then add a consumer using only their retained outputs. The A/B/C example demonstrates this alongside the existing host workflow.
- Fix shared-storage handling on BeeGFS clients with different local device numbers. Trust configured storage locations and use directory inode observations in recovery records, without creating root markers or comparing device numbers across hosts.

Unsupported pre-1.0 factories and records have no automatic conversion, migration, or adoption path; initialized storage cannot be relocated. Deployments provide Apptainer and prepared images, keep images stable after submission, and maintain the intended shared storage paths. Image observations are metadata, not content hashes or snapshots. Ordinary site mounts remain in effect, and replacement of an entire storage root is not detected.

The verified setup is Python 3.12, gwf 2.1.1, and Apptainer 1.5.4 on Linux local workers and Slurm. Validation includes real container execution, cleanup and Reuse, mixed graphs, image changes, retry and repair, and unrestricted Slurm checks for the BeeGFS correction; see the [validation record](https://github.com/MOMA-AUH/gwflow/blob/v0.4.0/docs/validation-v0.4.0.md) for evidence and limits. The release workflow built and tested the Conda artifact, published it to the [MOMA-AUH channel](https://anaconda.org/MOMA-AUH/gwflow), then installed the published package and passed the cleanup and Reuse check. See the [README](https://github.com/MOMA-AUH/gwflow/blob/v0.4.0/README.md) for setup and examples.
