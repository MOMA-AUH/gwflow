# gwflow v0.9.0

gwflow v0.9.0 adds automatic record compaction after Task completion and improves
interactive status details, job ordering, and log display.

### Highlights

- Successful completion consolidates attempt records without discarding submission,
  recovery, or lifecycle history. Each compacted attempt retains two metadata files
  and one directory, independent of job and retry counts. Logs and computation
  files remain outside this bound.
- Compaction is required for completion-job success. If compaction fails, dependent
  jobs remain blocked. An ordinary `gwflow run` retries unfinished completion work
  without repeating valid computation.
- Work cleanup preserves compacted records. Repair can restore individual records
  temporarily and compacts them again after successful completion.
- Interactive Task views show concise reasons with expandable details and list jobs
  in dependency order.
- Submission summaries use quieter styling. Wrapped logs stay anchored to the tail
  while the display layout settles, and log-view refresh handles concurrent closure.

### Compatibility and deployment

This remains a pre-1.0 release. The
[compatibility guidance](https://github.com/MOMA-AUH/gwflow/blob/v0.9.0/docs/reference.md#compatibility)
continues to apply. Before an upgrade, finish or cancel affected jobs and confirm
that every computation and lifecycle job is inactive. A cancellation request alone
does not establish inactivity. This release adds no migration or separate compaction
command for already-completed attempts.

The deployment profile remains Linux and Bash with Python 3.12, gwf 2.1.1, and
deployment-provided Apptainer 1.5.4 for containers. Automated checks use local
workers, real containers, and controlled Slurm commands.

The [compaction acceptance record](https://github.com/MOMA-AUH/gwflow/blob/v0.9.0/docs/validation/compaction-scale/README.md)
includes live Slurm execution on BeeGFS, interrupted compaction, late acknowledgements,
repeated Repair, and cleanup. Its scale checks preserve history while keeping the
metadata count fixed. These feature checks do not establish cross-version
interoperability, power-loss durability, or support for all filesystems.

### Setup and verification

```sh
conda create -n gwflow-090 --override-channels -c MOMA-AUH -c gwforg -c conda-forge 'gwflow=0.9.0'
conda activate gwflow-090
gwflow --version
```
