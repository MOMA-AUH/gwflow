# gwflow v0.11.2

gwflow v0.11.2 improves Slurm job identity checks and recovery from interrupted managed storage setup. It also extends installed-upgrade validation for JSON status consumers.

### Highlights

- Slurm observations and cancellation verify the exact Submission identity, preventing unrelated jobs from being mistaken for managed jobs. Incomplete scheduler records are handled separately, and recovered admissions are observed in batches.
- Status inspection handles truncated IDs for unrelated Slurm job arrays without rejecting the scheduler response.
- If initial managed storage setup is interrupted, resolve the reported storage problem and rerun `gwflow run`. Setup admits no jobs until ownership and Task initialization records are valid, and existing files without valid ownership evidence remain protected.
- Installed-upgrade comparisons include a preserved reference JSON status consumer and allow compatible additions to its handoff.

### Compatibility and deployment

This remains a pre-1.0 release. Before upgrading, finish or cancel affected jobs and establish that all computation jobs, lifecycle jobs, and their descendants are inactive. A cancellation request alone does not establish inactivity. See the [operating guide](https://github.com/MOMA-AUH/gwflow/blob/v0.11.2/docs/operating.md) and [compatibility guidance](https://github.com/MOMA-AUH/gwflow/blob/v0.11.2/docs/reference.md#compatibility).

The deployment profile remains Linux and Bash with Python 3.12, exactly gwf 3.0.0, and deployment-provided Apptainer 1.5.4 for containers. Local schedulers remain specific to each resolved workflow directory. The default local walltime remains one hour, including preparation and completion jobs.

Compatibility comparisons use the native gwf 3 bootstrap. They do not establish compatibility with earlier gwf 2 workflow state or the future stable compatibility baseline. This pre-1.0 release does not establish a stable baseline.
